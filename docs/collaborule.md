# 협업 규칙

## 브랜치 전략
- `main`: 배포용
- `feature/이름`: 각자 개발 작업용 (예: `feature/jihyun`)

## 커밋 메시지 규칙
- 형식: `타입: 설명`
- 예시:
  - `feat: Flask 앱 초기 구성`
  - `docs: 협업 규칙 작성`
  - `fix: EC2 설정 오류 수정`

## PR(Pull Request) 규칙
- 제목: `작업 요약 (이름)`
- 리뷰 후 `main` 브랜치로 merge
- 팀원 최소 1인 이상 리뷰 후 merge

## 기타
- 매주 `docs/weekN-실습명.md`에 실습 결과 캡처 및 설명 정리
